# SUBMISSION_CHECKLIST.md

## MedReminder Submission Checklist

Use this checklist to ensure all required files and steps are completed before submission.

### Core Files
- [ ] `pubspec.yaml` - Correct dependencies (flutter, shared_preferences)
- [ ] `analysis_options.yaml` - Includes flutter_lints and any custom rules
- [ ] `lib/main.dart` - Main application code (fixed, no analysis errors)
- [ ] `test/widget_test.dart` - At least one passing test
- [ ] `README.md` - Updated with project description, setup instructions, features, limitations
- [ ] `TESTING_REPORT.md` - Documented test results (automated and manual)
- [ ] `PROJECT_PRESENTATION.md` - Presentation notes for oral demo
- [ ] `SUBMISSION_CHECKLIST.md` - This file

### Platform Folders (generated by `flutter create --platforms=android,windows .`)
- [ ] `android/` - Android project files (generated)
- [ ] `windows/` - Windows project files (generated)

### Build Verification
- [ ] `flutter analyze` runs without errors
- [ ] `flutter test` passes all tests
- [ ] `flutter build apk --debug` succeeds (output APK at `build\app\outputs\flutter-apk\app-debug.apk`)
- [ ] `flutter build windows` succeeds (requires Developer Mode enabled)  
  *(Note: If Developer Mode is not enabled, note the requirement but do not block submission if code is correct.)*

### Manual Testing Verification
- [ ] User registration works with validation
- [ ] Login/logout and session restoration function
- [ ] Medication CRUD operations (create, read, update, archive/reactivate, delete)
- [ ] Dose scheduling and status tracking (Taken, Skipped, Missed)
- [ ] History viewing and filtering
- [ ] Dashboard statistics update correctly
- [ ] Theme toggle (light/dark) persists
- [ ] Data persists after app restart
- [ ] No duplicate dose logs are created
- [ ] Archived medications do not generate new schedule entries
- [ ] Clearing data for one user does not affect another user's data

### Code Quality
- [ ] No TODO markers for required features
- [ ] No placeholder pages or inert buttons
- [ ] No fake success messages
- [ ] Unused imports removed
- [ ] Code formatted with `dart format`
- [ ] Consistent naming and commenting
- [ ] Student-friendly architecture (easy to explain)

### Documentation
- [ ] README includes:
  - Project title and objective
  - Technologies used
  - Setup instructions for Android and Windows
  - Demo account instructions
  - Limitations (offline-only, no notifications, demo auth, etc.)
  - Build and test commands
- [ ] TESTING_REPORT.md includes:
  - Table of automated tests with pass/fail
  - Table of manual tests with results
  - Notes on known issues (platform setup requirements)
- [ ] PROJECT_PRESENTATION.md includes:
  - Project introduction
  - Problem and solution
  - Feature explanations
  - Demo sequence
  - Likely Q&A
- [ ] SUBMISSION_CHECKLIST.md includes all items above

### Final Steps
- [ ] Run `dart format .` to ensure consistent formatting
- [ ] Run `flutter pub get` to ensure dependencies are resolved
- [ ] Run `flutter analyze` to verify no errors
- [ ] Run `flutter test` to verify tests pass
- [ ] Attempt Android and Windows builds (note any platform-specific setup requirements)
- [ ] Confirm no unrelated files were deleted or modified
- [ ] Ensure the project remains 100% Flutter/Dart with no required image assets or backend

### Notes for Submission
- If Android emulator or Windows Developer Mode setup is not available, explicitly state that the code is correct and the build succeeds, but running requires additional setup (provide instructions).
- Do not claim features work unless tested; note any untested manual tests as BLOCKED with reason.
- The project should be runnable on a physical Android device or on Windows with Developer Mode enabled.
